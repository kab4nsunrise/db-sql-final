## Описание проекта: Сервис отслеживания посылок

В этом проекте разрабатывается приложение для отслеживания почтовых отправлений. Вы научитесь работать с базами данных (SQLite) в Go, реализовывать CRUD-операции, а также писать интеграционные тесты для проверки взаимодействия с БД. Сервис позволяет регистрировать посылки, просматривать список посылок клиента, изменять статус и адрес доставки, а также удалять посылки (с соблюдением бизнес-логики). Вам предстоит доработать готовый каркас приложения, реализовав недостающие функции и обеспечив их корректное тестирование.



## Общая концепция

Приложение представляет собой сервис, который управляет данными о посылках, хранящимися в базе данных SQLite. Каждая посылка имеет уникальный номер (автоинкрементный идентификатор), идентификатор клиента, статус, адрес доставки и дату создания. Сервис поддерживает следующие бизнес-правила:

- При регистрации новой посылки ей автоматически присваивается статус «зарегистрирована» (`registered`).
- Трек-номер посылки равен её первичному ключу в таблице.
- Изменение адреса доставки и удаление посылки допустимы **только** для посылок в статусе «зарегистрирована».
- После отправки (`sent`) и доставки (`delivered`) изменение адреса и удаление запрещены.



## Структура программы

Программа состоит из следующих компонентов:

- **`main.go`** – точка входа. В нём происходит подключение к БД, создание экземпляра `ParcelStore` и `ParcelService`, а также демонстрация работы функций сервиса (вывод результатов в консоль). Константы статусов (`ParcelStatusRegistered`, `ParcelStatusSent`, `ParcelStatusDelivered`) также объявлены здесь.

- **`parcel.go`** – содержит определение структур и реализацию логики:
  - `ParcelStore` – интерфейс для работы с БД (методы: `Add`, `GetByNumber`, `GetByClient`, `SetStatus`, `SetAddress`, `Delete`).
  - `ParcelService` – структура, которая принимает `ParcelStore` и реализует бизнес-логику (например, проверку статуса перед изменением адреса или удалением).
  - В этом файле вам нужно **реализовать пустые функции**, которые сейчас содержат заглушки. Все необходимые SQL-запросы и логика описаны в комментариях.

- **`parcel_test.go`** – интеграционные тесты, проверяющие корректность работы функций `ParcelStore` и `ParcelService`. Тесты используют реальную БД (файл `tracker.db`), поэтому требуют подключения. Вам предстоит написать тесты для каждой функции (добавление, получение, обновление статуса, обновление адреса, удаление) с учётом бизнес-правил.



## База данных

Используется SQLite. Структура таблицы `parcel`:

- `number` INTEGER PRIMARY KEY AUTOINCREMENT – номер посылки (трек-номер).
- `client` INTEGER – идентификатор клиента.
- `status` TEXT – статус посылки (одна из констант).
- `address` TEXT – адрес доставки.
- `created_at` TEXT – дата и время создания (хранится в формате строки, например, ISO8601).

Файл БД `tracker.db` создаётся автоматически при первом запуске, если его нет.


## Функциональные требования

В `parcel.go` необходимо реализовать следующие методы:

### Для `ParcelStore` (интерфейс)

- **`Add(p Parcel) (int, error)`** – добавляет новую посылку в БД. Возвращает присвоенный номер (число) и ошибку.
- **`GetByNumber(number int) (Parcel, error)`** – получает посылку по номеру. Возвращает структуру `Parcel` и ошибку (если не найдена).
- **`GetByClient(client int) ([]Parcel, error)`** – возвращает все посылки, принадлежащие указанному клиенту.
- **`SetStatus(number int, status string) error`** – обновляет статус посылки.
- **`SetAddress(number int, address string) error`** – обновляет адрес доставки.
- **`Delete(number int) error`** – удаляет посылку из БД.

### Для `ParcelService`

- Методы-обёртки, которые используют `ParcelStore` и добавляют бизнес-проверки. Например, перед изменением адреса проверяется, что статус посылки равен `ParcelStatusRegistered`, иначе возвращается ошибка. Аналогично для удаления.

Все эти функции уже объявлены, но тела пусты – их нужно написать, следуя комментариям и логике.


## Тестирование

В файле `parcel_test.go` вы должны написать интеграционные тесты, которые будут:

- Подключаться к тестовой БД (можно использовать отдельный файл или очищать таблицу после каждого теста).
- Проверять:
  - Добавление посылки и получение её по номеру.
  - Получение списка посылок клиента.
  - Обновление статуса.
  - Обновление адреса – успешное и с ошибкой, если статус не `registered`.
  - Удаление – успешное и с ошибкой, если статус не `registered`.
- Использовать подход табличных тестов (test tables) для покрытия различных сценариев.

Тесты должны выполняться без ошибок при запуске `go test`. Это гарантирует, что реализация функций корректна и бизнес-логика соблюдена.



## Запуск приложения

После реализации всех функций и тестов вы можете запустить приложение командой `go run .`. В консоли появятся сообщения, демонстрирующие работу сервиса (регистрация посылок, изменение статусов, вывод списков). Если всё сделано правильно, вывод будет содержать информацию о посылках, и программа завершится без ошибок.
